What it does

On a product with options, Zen Cart shows Starting at: $59.95 at the top of the page and leaves it there. The customer picks the $149.95 option, the page still says $59.95, and the first time they see the real figure is in the shopping cart. Some of them leave at that point.

Attribute Pricing Manager replaces that with a figure that changes the moment an option changes, and puts it where the customer is about to commit:

  License:  [ Developer - Unlimited Stores ( +$190.00 ) v ]

                    Total: $249.95
                     [ Add to Cart ]

Dropdowns, radio buttons, checkboxes, text fields with per-word or per-letter pricing, quantity-tiered attribute prices, price factors, one-time charges, specials and sales, tax, the customer's currency: the figure is worked out the way the shopping cart works it out, so what they see is what they will pay.

Why it exists

Zen Cart's "Starting at:" is honest but unhelpful. It tells the customer the lowest price they could pay and nothing about the price they are about to pay. Every option they choose makes the gap bigger, and the gap is discovered at the worst possible moment.

The obvious fix, an AJAX call back to the store on every change, is how the well-known Dynamic Price Updater does it. This plugin takes a different route so that it can run unchanged on every Zen Cart from v1.5.8 to v3.0.0: Zen Cart v1.5.8's ajax.php cannot load a class from a plugin directory at all, so an AJAX design would have needed a version branch. See How it works.

How it works

When a product page is built, the plugin works out, on the server and with Zen Cart's own pricing functions, the product's base price and what each attribute value adds or takes away. That data, plus the tax rate and the currency's format, goes into the page's <head> as one small JSON object. A script in the browser then reads the add-to-cart form and adds up whatever is selected, every time a selection changes. No request goes back to the server until Add to Cart is pressed.

The arithmetic follows shoppingCart::calculate() for a quantity of one: base price with specials and sales applied, each selected attribute's delta (including discounted attributes and price factors), floored at zero, tax added when the store displays prices with tax, and one-time charges kept separate because the cart adds those once per order rather than per item.

Nothing in the page is changed by PHP. The plugin observes one Zen Cart notifier, NOTIFY_HTML_HEAD_END, and everything visible is done by the script. Remove the plugin and the page is exactly as it was.

Installing

  1. Upload the zc_plugins/AttributePricingManager/ directory from the package to your store, so that it lands at <store root>/zc_plugins/AttributePricingManager/v1.0.0/. Nothing goes anywhere else.
  2. In your admin, go to Modules → Plugin Manager, select Attribute Pricing Manager and click Install.
  3. Open a product. The running total is there, in front of the Add to Cart button, labelled "Total:" and multiplied by the quantity box; the stock "Starting at:" heading stays where it was. Both of those are settings.

The plugin is switched on as soon as it is installed. Its settings are under Configuration → Attribute Pricing Manager.

If your store is itself a git checkout of Zen Cart, zc_plugins/.gitignore uses a deny-all rule with an allowlist; add !AttributePricingManager/ and !AttributePricingManager/** to it or git will not see the plugin. This has no effect on the plugin working.

What counts toward the total

ElementHandledNotes
Base priceYesWith specials and sales applied exactly as the cart applies them; a product priced by attributes starts from its raw price so its attributes carry the real prices.
Dropdown, radio, checkboxYesPlus and minus prefixes; "discounted" attributes go through the same sale/special calculation as the cart.
Text and file optionsYesThe option's flat price counts whenever the field is on the form, as it does in the cart. Per-word and per-letter pricing is counted as the customer types, with Zen Cart's own rules for free words, free letters and free spaces.
Price factorYesPercentage-of-price attributes, including the one-time variant.
Quantity-tiered attribute pricesYesThe tier for the quantity in the box, with the same tier-selection rule as the cart.
One-time chargesYesShown on their own line, not multiplied by quantity, tax applied as for the item.
Product quantity discountsYesApplied when "Multiply by the quantity box" is on. The tier prices are worked out on the server with the store's own function, so wholesale, specials and "discount from" behave as in the cart.
TaxYesAdded when Display Prices with Tax is true, at the product's tax class rate for the customer's location.
CurrencyYesConverted and formatted in the currency the customer has selected, symbols and separators included.
Wholesale pricing (v2.2+)YesA wholesale customer sees wholesale figures.
Free / Call for priceYesA free product totals its attributes only; a call-for-price product gets no running total at all, matching the page.
Read-only optionsYesNever charged, as they are never submitted.

Templates and selectors

The plugin finds its way around the page with two CSS selectors that are settings, because templates differ.

Stock price block selectors

What to hide (or write into). Zen Cart's own templates, responsive_classic and template_default on every release, put the price in <h2 id="productPrices">. The ZCA Bootstrap template wraps it in a card, #productsPriceTop-card, and can show a second one, #productsPriceBottom-card, below the attributes. The default list covers all three; a selector that matches nothing is harmless.

With the Top placement, the total is written into the heading inside the matched block, so a Bootstrap card keeps its frame.

Add to Cart container selector

Where to put the total. #cartAdd is the element that holds the quantity box and button in the stock templates, and the card body that holds the button in ZCA Bootstrap. The total is inserted immediately before the submit button inside it, so on the stock template it lands between the quantity box and the button, and on Bootstrap directly above the button.

If the selector matches nothing, the plugin looks for the form's submit button anywhere, then for the attributes block. If none of those exist, it gives up and shows the stock heading again.

To find your template's ids: open a product page, right-click the price, choose Inspect, and read the id of the heading and of the element around the Add to Cart button.

Customizing the look

The plugin's stylesheet is catalog/includes/templates/template_default/css/attribute_pricing_manager.css inside the plugin. To change it, copy that file to includes/templates/YOUR_TEMPLATE/css/ in your store and edit the copy: the plugin links the template's copy in preference to its own, so an upgrade never touches your changes. The same goes for the script, at .../template_default/jscript/attribute_pricing_manager.js.

The markup is:

<div class="apm-box" aria-live="polite">
  <span class="apm-label">Your Price:</span>
  <span class="apm-amount">$249.95</span>
  <span class="apm-onetime">
    <span class="apm-onetime-label">One-time charge: </span>
    <span class="apm-onetime-amount">$25.00</span>
  </span>
</div>

The one-time line is only present when that setting is on, and only visible when a chosen option has such a charge. aria-live="polite" means a screen reader announces the new figure when it changes.

Translating

The four visible strings are in catalog/includes/languages/english/extra_definitions/lang.attribute_pricing_manager.php. Copy that file to catalog/includes/languages/<your language>/extra_definitions/ inside the plugin and translate the values. APM_TEXT_SUFFIX is empty by default and is appended after the figure; a store that shows prices without tax might set it to ' plus VAT'.

Limitations

  • It needs JavaScript. Without it the page is exactly as Zen Cart made it: the stock "Starting at:" heading is only hidden once the script has somewhere to put the total.
  • Quantities above one are close, not exact, in one corner. A "discounted" attribute on a product with quantity discounts is priced by the cart through a quantity-aware calculation; the plugin prices it for one and multiplies. Products without quantity discounts, and attributes that are not marked discounted, are exact at any quantity.
  • Anything already in the cart is not added in. The total is for what is on this page. Zen Cart's mixed-quantity discount floor is honoured, though: if three are already in the cart, the tier prices reflect that.
  • Gift certificates take their price from the amount typed, which the plugin does not attempt to read.
  • The plugin does not touch category listings, search results or the shopping cart page.

Upgrading

Upload the new version's directory beside the old one, so both zc_plugins/AttributePricingManager/v1.0.0/ and the newer one are present, then in Plugin Manager select the plugin and click Upgrade. Your settings are kept: an upgrade refreshes the labels and help text of each setting but never its value. Delete the old version directory afterwards.

Uninstalling

In Plugin Manager, select the plugin and click Uninstall. That removes the configuration group and every setting. Then delete zc_plugins/AttributePricingManager/. No other file in your store was changed, and no table was created.

Troubleshooting

Nothing appears, and the stock price is still there

  • Is the plugin enabled in Configuration → Attribute Pricing Manager?
  • Does the product have attributes? With "Only on products with options?" set to true, plain products are left alone.
  • Is it a call-for-price or document product, or is the store in showcase mode? Those show no price anywhere, so the plugin stays quiet.
  • View the page source and search for attributePricingManager. If it is not in the <head>, the plugin decided not to act on this page for one of the reasons above. If it is there but nothing shows, the script could not find a place to put the total: check the selectors.

The figure differs from the cart

For a quantity of one they should agree to the cent. If they do not, note the product, the options chosen, and whether the product has a special, a sale, quantity discounts or a discounted attribute, and raise it on the support thread with those details. For quantities above one, see Limitations.

Two prices are showing

The stock heading is hidden by the selectors in "Stock price block selectors". Your template names its price heading something else; add its id there.

The total is in the wrong place

Change "Add to Cart container selector" to the element that holds your template's Add to Cart button.
